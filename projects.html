Zwift Data Viewer

Flutter Dart Riverpod Supabase Google Gemini AI SQLite Syncfusion Charts

Status: Production / Active. I'm currently rebuilding it as a web app, to get away from the app store hassles.

Problem

Cyclists using Zwift and Strava generate vast amounts of performance data, but analyzing this data to improve training and discover optimal routes is time-consuming. Athletes need intelligent insights that combine historical performance with AI-powered recommendations.

Technical Approach

Built a cross-platform mobile application (iOS, Android, Web) that integrates multiple data sources and provides intelligent analytics:

  • Real-time activity tracking with power, heart rate, and elevation analysis
  • AI-powered route recommendations using Google Gemini (70% algorithmic, 30% AI)
  • Offline-first architecture with seamless online/offline transitions
  • Multi-source data aggregation (Strava API, Supabase cloud, SQLite local cache)
  • Interactive performance visualization with Syncfusion Charts

Architecture Highlights

Hybrid 3-Tier Data Architecture: Implements cache-aside pattern with Strava API as source, Supabase as cloud database, and SQLite for local caching. Intelligent sync strategy handles conflicts with last-write-wins, treating Supabase as source of truth.

AI Integration: Hybrid recommendation engine combines algorithmic analysis (performance matching, progressive challenge) with Google Gemini 2.5 AI for pattern recognition. Graceful fallback ensures functionality even when AI is unavailable.

State Management: Riverpod providers handle complex state across connectivity changes, with FutureProvider for async data loading and StateNotifierProvider for mutable state. Family providers enable parameterized queries.

Authentication Flow: Multi-stage auth using Strava OAuth as primary, then Supabase auth with automatic token refresh and secure storage.

Key Learnings

Offline-first architecture requires careful consideration of conflict resolution strategies. Connection pooling and lazy loading are essential for mobile performance. Combining algorithmic and AI recommendations provides better results than either alone - algorithms handle edge cases where AI may be unreliable.

Impact

Production app with active users. Demonstrates sophisticated mobile architecture, AI integration, and data synchronization at scale. Shows ability to build complex, data-intensive applications that work seamlessly across platforms.

LEGO Train Controller

React TypeScript Vite Python FastAPI Bluetooth LE MQTT Raspberry Pi Pico REST API IoT

Status: Production / Active

Problem

LEGO Powered Up trains and switches require proximity for manual control. Remote automation and multi-device coordination is challenging, and running several trains on one layout risks collisions without a way to track where each train actually is. Hobbyists need a system that bridges digital control with physical hardware, is easy to reach from any device, and can optionally run itself.

Technical Approach

Built a React/TypeScript web app and a Python/FastAPI backend that controls LEGO Powered Up and Technic hubs over Bluetooth Low Energy, with an optional RFID-based dispatcher for fully autonomous operation. The control surface started as a Flutter mobile app and was rebuilt as a web UI so it can be reached from any browser on the network without installing anything:

  • Manual train operation with speed and direction control over a persistent, auto-reconnecting BLE/GATT connection to stock hub firmware
  • Track switch management (Motor and DCMotor switches, up to 4 ports per hub) with command verification and reliability stats
  • Optional RFID autonomous dispatch: Raspberry Pi Pico 2 W + RFID readers report train position over MQTT, so the system can hold trains at block boundaries, auto-align switches, resolve contention between trains, and fail safe via a watchdog if a train misses an expected tag. Track/switch/sensor wiring for the dispatcher is generated directly from a layout drawn in the LEGO Track Designer project's topology export, rather than mapped out by hand
  • Real-time status monitoring (connectivity, speed, direction, signal strength, connection quality)
  • Multi-device simultaneous control from any browser on the network
  • API secured with per-key auth and per-endpoint rate limiting

Architecture Highlights

Hardware Integration: Trains are controlled directly over BLE/GATT against stock LEGO Powered Up firmware (no custom firmware upload needed); switches run a Pybricks-based broadcast/observe protocol on Technic Hubs. A custom BLE scanner handles forced cleanup and auto-recovery.

Web Client: React 19 + TypeScript app built with Vite, using React Context for state management and polling the backend (configurable, default 1s) to keep the UI in sync. Runs anywhere on the network as a static build, versus the earlier Flutter app which required a device-specific install.

REST API Design: FastAPI backend exposes train control (POST /train), switch control (POST /switch), status retrieval (GET /connected/trains, GET /connected/switches), a health check, and connection reset (POST /reset); every mutating endpoint requires an X-API-Key header and is rate-limited per client IP.

Autonomous Dispatch: A separate dispatcher package (track model, block manager, MQTT bridge, watchdog) runs as a background task inside the same service, driving trains/switches through the same controllers the REST API uses. It can run standalone in a mock mode with no hardware attached, for testing the routing logic in isolation.

Data Models: TypeScript types on the web client; pydantic-settings for backend configuration.

Key Learnings

IoT projects require careful abstraction layers - separating BLE complexity from application and dispatch logic makes the system more maintainable, and paid off directly when the control surface itself was swapped from a Flutter app to a web client without touching the backend. Polling vs push notifications involves trade-offs; polling is simpler but less efficient. Coordinating multiple autonomous agents on shared physical infrastructure (track blocks) surfaces real distributed-systems problems - contention, deadlock, and failsafe behavior all needed explicit handling. Physical hardware debugging is fundamentally different from software - Bluetooth signal strength and physical interference matter.

Impact

Demonstrates IoT and hardware integration skills rarely seen in typical software portfolios, extended into distributed coordination: collision-protected, multi-train autonomous operation driven by RFID position tracking over MQTT. Shows ability to bridge digital and physical worlds, secure and rate-limit a hardware-facing API, and design for production deployment (systemd service, structured logging), with a browser-based client that lowers the barrier to entry versus a native mobile install.

LEGO Track Designer

React JavaScript Vite Material-UI Tailwind CSS SVG Vitest

Status: Active

Problem

LEGO train enthusiasts need to plan complex track layouts before physical construction. Planning on paper lacks precision, while physical trial-and-error wastes time and pieces. Digital tools need to be intuitive, accurate, and support iterative design, and ideally the layout shouldn't have to be redrawn by hand to wire up automated control.

Technical Approach

Built a browser-based visual track designer with drag-and-drop interface, plus a one-click export of the layout's control topology for the LEGO Train Controller project:

  • Drag-and-drop track pieces: straight, quarter-length straight, left/right curves, left/right switches, left/right motorized switches, and sensor-marker variants of the straight and curve pieces
  • Piece dimensions and connection points follow official LEGO track specifications, with switch geometry traced from real reference parts rather than approximated
  • Selection: click, shift-click to multi-select, or shift-drag a marquee to select a group
  • Rotate, flip, copy, and delete, all selection-aware
  • Automatic snapping between compatible connection points during drag-and-drop
  • Undo, and pan/zoom around the canvas
  • Save/load track designs as JSON files
  • Export Track Map: traces the layout into a switch/sensor topology graph and downloads it as both a JSON file for a train-control program to consume, and a standalone interactive HTML viewer for visually checking the wiring

Architecture Highlights

Component Architecture: Modular React design with TrackDesigner as main orchestrator, TrackPieces defining piece geometry and SVG paths, and specialized hooks for drag behavior, history management, and canvas navigation.

Custom Hooks: useTrackHistory implements undo with immutable state operations, useTrackDragging handles complex drag-and-drop with collision detection and multi-select/marquee logic, usePanZoom manages canvas transformations for smooth navigation.

Geometric System: Pure functions handle track piece transformations (rotation, flipping), connection point calculations, and automatic piece snapping, calibrated against official LEGO RC Track and Standard Gauge specs. SVG-based rendering ensures crisp visuals at any zoom level.

Topology Export: Walks the layout's connection graph outward from every switch, collapsing intervening straight/curve/sensor pieces into a single edge per switch-to-switch connection, labeled by exit (trunk/straight/diverge) so it lines up with how a train-control program would name a switch's routes. RFID sensor pieces become tagged points along those edges. Switch-free loops (e.g. a plain oval) are traced separately, and any exit with real track that never reaches another switch is flagged as a dangling/broken connection instead of silently disappearing. The same graph drives both the downloadable JSON and a self-contained pan/zoom SVG viewer with hover tooltips, generated client-side with no dependency on the designer app to view it.

State Management: Immutable state updates through history system enable reliable undo. All track operations are pure functions, making behavior predictable and testable, and covered by a Vitest test suite.

Key Learnings

Interactive canvas applications require careful separation between UI state (pan/zoom) and domain state (track layout). Custom hooks enable clean separation of concerns - drag behavior, history, and canvas navigation are independently testable. SVG coordinate systems need careful handling when combining transformations, rotations, and user interactions. Matching real-world part geometry (rather than approximating it) paid off once switches needed to snap and align precisely. Immutable state patterns make undo trivial but require discipline in state updates. Reducing a freeform layout to the graph a control program actually cares about (switches, sensors, and how they connect) forces you to explicitly define and validate what "connected" means, rather than leaving it implicit in pixel positions - and surfacing dangling routes instead of hiding them turned a possible silent bug in the exported map into a visible one in the editor.

Impact

Demonstrates advanced React patterns, geometric algorithms, and interactive UI design. Shows ability to build specialized design tools with complex user interactions and precise, real-world-accurate geometry. Clean architecture and test coverage make the codebase maintainable and extensible for future features like track validation and 3D preview. The topology export turns the designer from a standalone planning tool into the front end of a small pipeline - track layouts drawn here feed switch/sensor wiring directly into the LEGO Train Controller's RFID dispatcher, rather than that mapping being redone by hand.
